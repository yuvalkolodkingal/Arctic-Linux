# Arctic Linux 1.2

Arctic 1.2 retains the Fedora 44 base, Zen browser, and DNF, Flatpak and Nix integration from 1.1.

- **Taskbar visibility:** choose Always visible, Auto-hide or Dodge windows in Appearance. Dodge hides when a visible window overlaps the selected edge, with delayed hiding, pointer/keyboard reveal and open-menu pinning. All four edges are supported. Legacy Auto-hide preferences remain readable. The live installer keeps its bar visible.
- **Mango support:** the packaged compositor supplies coalesced geometry notifications for floating moves and resizes. Dodge requires the updated compositor session; until the next login, an older running compositor leaves the bar visible and Settings explains the requirement.
- **Get Apps:** six cards in two rows: Flathub, Fedora and Web apps; then Nix, Terminal and Console. Remove Apps remains available from its standalone launcher.
- **Updates:** enabled Arctic repositories must provide metadata before a check can succeed. Settings reports failed checks, retains a valid queued download on failure, allows another check while updates are queued, and displays the last successful check time. Optional repositories retain their existing availability policy. Package signatures and repository trust settings remain unchanged.

## Validation and scope

The combined source is qualified through CI, including RPM builds, real DNF fixture transactions, Python/Node tests and headless Settings/menu checks. Native Dodge acceptance uses isolated Mango sessions; physical monitor and hardware behavior remains separate. The ISO acceptance path checks an encrypted installation under SELinux Enforcing, Nix app ownership and persistence, graphical launch, Zen, compositor capability, taskbar preferences and reboot. Record the exact build commit, checksum and acceptance results with the delivered image; this document does not declare a build successful before it finishes.

A Settings-backend fixture test executes a real DNF offline transaction in a container. It does not prove graphical Polkit interaction or a native offline-update boot. Nix engine-version migration is only proven when a newer engine is actually available and installed. See [Nix operating limits](../nix/VALIDATION.md) for the remaining compatibility and hardware scope.
