# Arctic Linux 1.2.1 publication runbook

This runbook records the exact order for publishing the retained, qualified
Arctic Linux 1.2.1 image. Commands containing placeholders are inert until the
placeholders are replaced from reviewed GitHub API responses. Do not use the
ordinary `iso.yml` release switch or a `v1.2.1` tag push for this release; the
only final publisher is `publish-qualified-20261008.yml`.

## 1. Freeze and inspect the artifact-only producer

Reuse an existing successful first-attempt producer when it is built from the
intended source. Do not dispatch a duplicate while one is running. If a new
producer is required, first make `main` equal the reviewed product source, then
dispatch these exact inputs:

```sh
SOURCE_SHA=$(git rev-parse origin/main)
gh workflow run iso.yml --repo yuvalkolodkingal/Arctic-Linux --ref main \
  -f expected_source_sha="$SOURCE_SHA" \
  -f release=false -f prerelease=true -f draft=false \
  -f nix_acceptance=false -f performance_acceptance=false \
  -f performance_mode=frozen-external-paired-v1 -f boot_test=true
```

The selected run must be `workflow_dispatch`, attempt 1, successful, and have
`release=false`, `performance_acceptance=false`,
`performance_mode=frozen-external-paired-v1`, and `boot_test=true`. Its single
`arctic-linux-iso` artifact must remain unexpired. Record the API identity and
download the retained bytes for inspection:

```sh
REPO=yuvalkolodkingal/Arctic-Linux
RUN=<producer-run-id>
gh api "repos/$REPO/actions/runs/$RUN" > producer-run.json
gh api "repos/$REPO/actions/runs/$RUN/jobs?filter=all&per_page=100" > producer-jobs.json
gh api "repos/$REPO/actions/runs/$RUN/artifacts?per_page=100" > producer-artifacts.json
rm -rf out/final-producer
gh run download "$RUN" --repo "$REPO" --name arctic-linux-iso --dir out/final-producer
find out/final-producer -maxdepth 2 -type f -print
sha256sum out/final-producer/*.iso
stat -c '%n %s' out/final-producer/*.iso
sha256sum out/final-producer/PERFORMANCE-PLAN.json
```

Build one image object, used byte-for-byte in every execution manifest:

```json
{
  "run_id": 0,
  "artifact_id": 0,
  "archive_bytes": 0,
  "archive_sha256": "<artifact API digest without sha256:>",
  "source_sha": "<40 hex producer head SHA>",
  "name": "Arctic-Linux-1.2-candidate-<run-id>-1-x86_64.iso",
  "bytes": 0,
  "sha256": "<ISO SHA-256>",
  "producer_mode": "frozen-external-paired-v1",
  "producer_receipt_sha256": "<PERFORMANCE-PLAN.json SHA-256>"
}
```

Require `bytes < 2000000000`; the preferred target is `< 1600000000`. Verify
the producer receipt reports successful `uefi-try`, `bios-install`, and
`uefi-safe` startup. A successful build alone is not qualification.

Review and push the preparation commit with none of the six marker paths

## 3. Review and pin evidence

For every run, query both the run and artifact endpoints. Record `run_id`,
`source_sha`, `artifact_id`, API `size_in_bytes` as `archive_bytes`, and the API
artifact `digest` without its `sha256:` prefix as `archive_sha256`:

```sh
QUAL_RUN=<qualification-run-id>
gh api "repos/$REPO/actions/runs/$QUAL_RUN"
gh api "repos/$REPO/actions/runs/$QUAL_RUN/jobs?filter=all&per_page=100"
gh api "repos/$REPO/actions/runs/$QUAL_RUN/artifacts?per_page=100"
```

Only attempt-1 successful runs and unexpired artifacts qualify. The UEFI/BIOS
reliability artifacts must be distinct matrix-job artifacts from one run. The
two dictation artifacts must be distinct matrix-job artifacts from one run and
the same fixture manifest. Download every artifact, run its contract checker,
and review the required taskbar, dictation-indicator and installer PNGs. Populate
`taskbar_media_review`, `dictation_media_review`, `installer_media_review`,
`installer_active_media_review`, and the aggregate native `media_review` using
the actual archive and image hashes. Never mark an unavailable visual or audio
review passed.

## 4. Prepare the publication manifest

On `codex/publish-qualified-20261010`, populate
`tools/qualified-release/manifest.json` with:

- `ready: true`, `publication_approved: true`, `release_acceptance: false`, and
  `tag: v1.2.1`;
- `main_sha` equal to the source of the stable repository run proven by the
  same-image update lane;
- the exact common image object;
- successful performance, native, update, both reliability, both dictation and
  both installer artifact pins;
- every required manual media-review object; and
- the complete execution-file inventory returned by
  `publication_files(manifest)`, with SHA-256 values from that checkout.

The current `main` may be a later documentation-only commit. It must descend
from `main_sha`, have one successful first-attempt `ci.yml` run, have no product
change since the image source, and have no open pull requests. Any product or
publication-helper change on `main` requires the corresponding new checks; a
product change requires a new ISO.

Run the publication controls locally. They are synthetic/read-only and do not
publish:

```sh
python3 -B -m unittest discover -s tools/tests -p test_qualified_release.py -v
python3 -B -m unittest discover -s tools/tests -p test_external_performance_publication.py -v
python3 -B -m unittest discover -s tools/tests -p test_release_torrent.py -v
python3 -B -m unittest discover -s tools/tests -p test_release_retraction.py -v
```

Review and push this preparation with no publish marker. The final activation
must again be one marker-only child and one push:

```sh
PARENT=$(git rev-parse HEAD)
test ! -e .github/qualification-20261010.publish
printf '%s\n' "$PARENT" > .github/qualification-20261010.publish
git add .github/qualification-20261010.publish
git commit -m "Publish reviewed qualified Arctic Linux 1.2.1"
test "$(git diff --name-only HEAD^ HEAD)" = .github/qualification-20261010.publish
git push origin HEAD:refs/heads/codex/publish-qualified-20261010
```

The publisher revalidates every run, artifact, execution hash, image byte,
source relationship, current `main`, CI/stable run and open-PR gate. It creates
the exact ISO checksum and torrent, uploads a draft, verifies all uploaded asset
digests, rechecks `main` and open PRs, and only then makes the release public.
It subsequently downloads the complete public ISO and verifies the first and
last HTTP torrent piece ranges. If that post-publication check fails, the
workflow returns only its own receipt-bound release to draft.

## 5. Verify the public result and stable update path

Do not report success until the publisher and its `release-download-verification`
artifact pass. Independently query and download the public release:

```sh
gh release view v1.2.1 --repo "$REPO" --json url,isDraft,isPrerelease,tagName,targetCommitish,assets
rm -rf out/public-v1.2.1 && mkdir -p out/public-v1.2.1
gh release download v1.2.1 --repo "$REPO" --dir out/public-v1.2.1
(cd out/public-v1.2.1 && sha256sum -c Arctic-Linux-1.2.1-x86_64.iso.sha256)
(cd out/public-v1.2.1 && sha256sum -c Arctic-Linux-1.2.1-x86_64.iso.torrent.sha256)
python3 -B tools/qualified-release/torrent.py verify-public \
  --iso out/public-v1.2.1/Arctic-Linux-1.2.1-x86_64.iso \
  --torrent out/public-v1.2.1/Arctic-Linux-1.2.1-x86_64.iso.torrent \
  --tag v1.2.1 > out/public-v1.2.1/webseed-verification.json
```

Confirm the release target equals current `main`, all five release assets have
the expected GitHub digest, and the full-download result matches the qualified
byte count and ISO SHA-256. The torrent proof supports an immutable GitHub HTTP
seed and first/last range reads; it does not claim an active tracker or peer.

Verify stable remains the pinned signed source before publishing update
instructions:

```sh
curl -fsS https://yuvalkolodkingal.github.io/Arctic-Linux/repo/stable/fedora-44/PUBLISH-INFO.json
sudo dnf5 --refresh --setopt=gpgcheck=1 --setopt=repo_gpgcheck=1 \
  --repo arctic check-update
```

On the qualified installed VM, retain the evidence for `arctic-update channel`,
`arctic-update now`, `arctic-update apply`, the offline transaction reboot,
changed higher-EVR Arctic packages, stable signatures, a new boot ID, preserved
user data and Nix GUI/profile persistence.

Finally merge the reviewed release/wiki documentation into `main` only when its
pending fields have been replaced by the exact qualified evidence. Confirm the
automatic `wiki.yml` run succeeded and compare the rendered wiki with
`docs/wiki/`. Documentation may link the public release and verification
artifact; it must not claim unrun hardware, GPU, microphone, tracker/peer or
performance results.
