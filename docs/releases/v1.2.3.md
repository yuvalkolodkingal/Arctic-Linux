# Arctic Linux 1.2.3

Arctic Linux 1.2.3 keeps the Fedora 44 base and the 1.2.2 desktop. It changes how updates
arrive, fixes the colours that follow the wallpaper, and starts quicker.

- **Updates install while you work.** Updates are plain `dnf` now: once a day they are
  downloaded (ten at a time) and installed in the background, and `sudo dnf upgrade` does
  exactly the same. Nothing waits for a restart any more. Only a new kernel, a graphics driver
  or firmware needs one, and then the bar says **Restart when you like**; the computer never
  restarts by itself. An app that is updated while open keeps its old version until you reopen
  it, and the desktop bar picks up its new version at the next login. A snapshot is still taken
  around every update. `arctic-update install restart` brings back updates at start-up.
- **Two kernels instead of three**: the one that is running and the newest. Each new kernel
  replaces the older spare.
- **One passphrase when updates are installed at start-up.** For those who keep updates at
  start-up, and for release upgrades: that boot no longer ends with a second full restart
  unless a kernel, driver or firmware changed, so an encrypted disk is unlocked once.
- **Colours follow every wallpaper.** Arctic's own photographs were treated like the three
  drawings and reset the desktop to the default Polar night or Winter colours. Every photo
  colours the desktop now; only Snowfield, Aurora and Fox keep the fixed colours. Automatic
  wallpaper rotation recolours the desktop with each picture again (1.2.2 had stopped that).
  **Match colours to wallpaper** still turns all of it off.
- **A shorter boot menu.** On a computer with only Arctic Linux the boot menu starts it after
  3 seconds instead of 5; any arrow key still stops the countdown. (New installations.)
- **Fewer disk writes.** The btrfs subvolumes are mounted with `noatime`. (New installations;
  on an existing one, add `noatime` to the btrfs lines of `/etc/fstab`.)
- **Compressed swap in memory (zram)** is a named part of the image.

Existing systems on the stable channel get all of this with their next update. The first
update after 1.2.2 is still installed the old way (at a restart); from then on updates install
while you work.
