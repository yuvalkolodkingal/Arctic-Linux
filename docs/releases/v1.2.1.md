# Arctic Linux 1.2.1

Arctic Linux 1.2.1 is the smaller replacement image for x86_64 systems. It keeps the Fedora 44
base and adds the current lightweight desktop, the project photo collection, direct official
VoxType integration, and the installer, taskbar and update fixes described below.

> **Publication status:** prepared, but not published. Replace every pending value in the
> qualification record only from the final retained image and its reviewed evidence. A source
> test or an ISO build by itself is not release qualification.

## What changed

- **Lighter defaults:** GNOME Web (Epiphany), Foot, GTK3 PCManFM, XArchiver, Celluloid,
  FeatherPad, Nano and Fish/Bash. Larger browsers, editors and office suites remain optional.
- **Taskbar and screen frame:** Always visible, Auto-hide and Dodge windows work with the bar on
  any edge. The frame inset follows the chosen edge and scale while the bar keeps the correct
  exclusive zone; each output has one bar. Fullscreen and covered surfaces do not leave a
  duplicate bar behind.
- **Installer restoration:** changing virtual terminals or temporarily losing the hosting output
  restores exactly one visible installer, on the same page, with the keyboard choice and running
  installation state retained.
- **Desktop fixes:** the full-battery icon, lock-screen clock, wallpaper settings, separate
  **Remove apps** menu and repository-aware update detection are included.
- **Updates explain themselves:** a **What’s New** card appears once for each Arctic package
  update on an existing account. **Settings → Updates → Release notes** or
  `arctic-shell-ipc whatsnew open` opens the current notes again.

## Official VoxType dictation

Arctic uses the upstream [VoxType 1.1.1](https://github.com/peteonrails/voxtype) daemon directly;
VoxType itself records, transcribes and inserts the text. Arctic installs and verifies it, supplies
safe local defaults, starts it from the explicit Mango shortcut and presents its status. Its
multilingual Whisper model supports Hebrew, English and automatic language detection. Audio
and transcription stay on the computer; Arctic disables remote inference, VoxType's input-device
hotkey listener, transcript notifications, clipboard fallback and transcript post-processing.
This upstream fix release improves quiet-microphone VAD, cancellation races, Vulkan device/startup
selection, paste-driver ordering, clipboard latency and config editing. Existing 1.1.0 systems
reuse their verified model and download the new signed executable through the retryable setup queue.

The ISO contains the setup, status UI and Mango shortcuts, while the VoxType executable and model
weights stay outside the live image:

- An **online OS installation** downloads the compatible signed VoxType CPU binary and pinned
  model, verifies the signatures, sizes and SHA-256 hashes, and prepares the user service.
- An **offline installation** finishes normally and queues a retryable first-boot setup. Settings
  says that dictation is not ready until the engine, model and per-user configuration are valid.
- A download failure or timeout does not fail the OS installation. Use **Settings → Dictation →
  Set up / retry…** after connecting.
- Press **Super + Ctrl + X** to start, then press it again to stop, transcribe and insert. The first
  activation starts official VoxType and loads the model; later recordings reuse it for the session.
  Press **Super + Ctrl + Backspace** to cancel. The recording/transcribing indicator stays visible.
- Vulkan acceleration is optional. If it fails, the error remains visible; select **CPU** and make
  a new recording. Arctic does not claim an automatic GPU-to-CPU retry.

|---|---:|
| Baseline + Whisper Small | 506,440,871 bytes (506.4 MB) |
| AVX2 + Whisper Large v3 Turbo Q5 | 593,457,131 bytes (593.5 MB) |

## Wallpapers

The built-in backgrounds now use the project's 28-photo collection. Fresh accounts start with
*City Afterglow*; updates keep each existing account's current wallpaper and custom choices.

The collection includes *Ember Clouds, City Silhouette*, the artist's original 2048 × 1152
master, preserved without regeneration or upscaling. Its SHA-256 is
`7af8cb5ce0d87773109d759afdd1d14ef22ce7e84fdc1533da1539083cd11b0b`.

Delete on a packaged Arctic wallpaper hides it for that account and excludes it from scheduled
rotation. **Restore hidden Arctic wallpapers** brings it back. The shared RPM-owned image remains
installed for other accounts, and an active wallpaper must be changed before it can be hidden.
Personal pictures can be deleted normally.

## Updating an existing installation

The release uses the signed stable `arctic` repository. The testing channel is not required.
Existing systems keep their app choices, wallpapers and personal settings.

```sh
arctic-update channel
arctic-update now
arctic-update apply
```

If `channel` reports testing, run `arctic-update channel stable` before `now`. Save your work
before `apply`; it restarts into the prepared offline transaction. The Arctic signing-key
fingerprint is `80F75DE9A23B632246FD1FF1BD1A642B5436645A`.

## Paired performance observations

[Run 38841063654](https://github.com/yuvalkolodkingal/Arctic-Linux/actions/runs/38841063654)
passed the frozen six-boot regression and precision gate: three interleaved installed KVM boots
per image, with a fresh overlay for every boot. The widest application-map observation interval
was 0.600 ms, within the unchanged `min(5 ms, 2.5%)` limit. Medians compare the v1.2.0 baseline
with this candidate:

| Observation | v1.2.0 baseline | v1.2.1 candidate | Difference |
|---|---:|---:|---:|
| systemd boot total | 25.689 s | 26.012 s | +1.26% |
| installed root allocation | 6,063,443,968 B | 4,473,966,592 B | -26.21% |
| normalized process PSS | 1,006,285,824 B | 984,248,320 B | -2.19% |
| pristine process PSS | 971,501,568 B | 978,673,664 B | +0.74% |
| first terminal map | 0.194 s (Kitty) | 0.064 s (Foot) | -66.80% |
| first file-manager map | 1.730 s (Nautilus) | 0.478 s (PCManFM) | -72.35% |
| first browser map | 3.665 s (Zen) | 2.894 s (Epiphany) | -21.03% |

The application rows compare the configured role defaults, so they are cross-application
observations rather than measurements of the same program. The sample has only three boots per
image and no confidence interval. QEMU/KVM, virtual graphics, different Fedora kernel/package
inventories, warm host storage and shared-library caches, and the observer itself are confounders.
Passing the gate establishes that no measured regression crossed its acceptance limit; it does
not by itself prove a general optimization or predict physical-hardware performance.
