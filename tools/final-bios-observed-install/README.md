# Disabled observed BIOS installation lane

This separate all-ADD namespace targets the same exact retained F10 ISO and
unchanged SourceA. Its new manifest starts with `ready: false`; no activation
marker is included. The former BIOS namespace, workflow, marker and CI bytes
remain unchanged.

The runner invokes the exact original BIOS main code object in an isolated
dependency namespace. Original execute, cleanup, argument construction, report
validation, whole-UART privacy screening, PNG validation and publication
functions retain their original code and globals. Explicit adapters supply the
new first-ADD admission, accepted 5c74 observer, derived guest bundle, one shell
transport substitution and failure-only finite status fields. The complete
embedded install driver, original authentication, BIOS/offline tuple, 2400-second
install and 6600-second host limits remain unchanged.

The accepted observer identifies only owned Source exception/return sites and
fixed assertion labels. Finite host cause records are retained before original
cleanup. They may be added to failed `host-status.json` only after a second
unchanged whole-text privacy gate. Failed UARTs, logs and PNGs remain private;
successful originals still require every original report/security/privacy gate.
No failure record supplies installation, input delivery, PAM or image acceptance.

The workflow is limited to a new branch, a sole first ADD of its new marker and
attempt one. Admission verifies every Source/execution pin and the retained
producer before its first API response. Root must separately peer and prepare
the ready-only tree and public first ADD. There is no dispatch in this Source
leaf and no qualification allowance.

Ordinary BIOS login still uses the old SourceA keyboard behavior. Native focus
fixtures and the separately reviewed UID challenge are not imported. Source
controls use explicitly synthetic Docker/QMP metadata or owned Python children;
they do not constitute a VM installation or an actual failure-cause diagnosis.
