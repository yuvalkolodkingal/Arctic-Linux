# Installed taskbar qualification

This supplements the frozen eight native gates. It is preparation until a rebuilt
ISO, exact source and reviewed execution head have been pinned. The native
manifest is disabled, retains the historical candidate identity for reference,
and has no activation marker added by this change.

The actual installed Mango shell is exercised with two virtual GPU outputs,
scales 1, 1.5 and 2, and every bar edge. Each of the 24 cases checks frame/bar
reservation through maximized Foot geometry, covered Auto/Dodge surfaces,
fullscreen Auto/Dodge/Always transitions, physical hide/reveal/conceal pixels,
mapped layer counts and exposed frame pixels. Mango IPC does not expose raw
exclusive-zone values; the report states that geometry is the observer. Virtual
outputs and a virtual pointer do not qualify physical monitors or GPUs.

The fixed test CD contains the original native helper, taskbar checker/runtime,
two compiled Wayland probes and a context bound to ISO bytes/SHA, built source,
execution commit, helper/native/ELF hashes and a random token. Probe compilation
runs in the prepared Fedora tool container, records exact C/XML hashes and RPM
versions, and never adds the compiler or development packages to the image.
The supplemental native host image also includes the official QEMU D-Bus and
OpenGL UI modules, a private bus daemon and the typed D-Bus command-line tool.
Its immutable image ID, host tool hashes and module/package versions are retained.

Two advertised scanouts alone do not connect two monitors. The taskbar fixture
starts QEMU paused with a root-only private D-Bus display, discovers two graphical
heads of the owned fixed virtio GPU and applies the official `SetUIInfo` method
before explicitly continuing the VM. It checks the QEMU service PID/UID and bus
owner throughout; no listener or desktop bus is used. Both host receipts are
retained, but the installed helper must still observe exactly two enabled Mango
outputs. The default fixture-free VM devices and performance preparation stay
unchanged.

All taskbar records and full PNG bytes use the guarded named virtio-serial output
`arctic-taskbar-evidence`. The collector verifies canonical character-device and
sysfs identity; the QEMU backend writes only an owned test output file. A small
UART completion receipt binds the fully written port END record to the original
installed native boot, UID and session. There is no UART evidence fallback or
shared host directory. Default QEMU construction remains byte-for-byte pinned;
additional fixture devices and CPU/network selection use separate wrappers.

The collector preserves up to 512 regular files, 4 MiB each and 128 MiB in total.
It rejects symlinks/special files and sends ordered, bounded zlib/base64 chunks.
The host verifies complete file/serial report equality, independent pixel
observations, all 480 immutable PNGs including conceal observations, trace
completeness and the exact cleanup/security fields. Structurally authenticated
failed reports are retained before acceptance fails. Raw port bytes remain
private; upload includes only a short bounded prefix and original byte/hash
metadata plus extracted files. Overflow or trace omission fails qualification.

The checker has a 30-minute deadline, export has a further bounded 10 minutes,
and only this explicit taskbar bundle extends the original one-hour installed
collection budget. It runs once and must restore exact preferences, output
scales, windows, pointer/workspaces and one bar per output. SELinux enforcement,
audit telemetry and no new AVCs remain required.

Publication additionally requires the passed transported state to match the
same-image native execution, canonical installed source hashes and the fresh
Wayland Foot PID/start-time/client/ELF proof. `taskbar_media_review` must bind a
passed visual review to that exact ISO, native artifact and every transported PNG
hash. Source controls, arithmetic checks or a retained historical image cannot
replace this real VM run and visual review.
