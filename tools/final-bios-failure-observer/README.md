# Disabled BIOS failure observability Source

This all-ADD namespace observes the exact BIOS180 execution helper and its
original SourceA test-install driver. It has no workflow, activation marker or
operational CLI. `composition.py` refuses invocation from the command line;
the manifest is `ready: false` and `release_acceptance: false`.

`stage_harness` changes one transport command from inline Python to the new
entry module. The complete embedded DRIVER, original VM library, commands,
arguments, input timing, authentication, 2400-second installation budget and
6600-second host budget remain unchanged. The original stage functions and
line tables are compiled from identical bytes and their globals stay intact.

The trace records only exact Source return sites for nonzero original stage
results, executed `ok = False` sites, and exact Source-owned raising/require
sites. Records contain fixed Source labels and whole Source checksums. No
exception argument, message, repr, transcript, credential, private path or
operand checksum is read or exported. Foreign functions, changed code objects,
changed line tables, changed globals and unknown channel rows cannot supply a
Source assertion. Observer emission failures preserve the original exception
and return values. Existing tracing is preserved by leaving observation off.

`derive_guest` retains every original decoded module and original failure
handler, adding the same observer around the original guest main function.
The exact original primary checker, retained privately by that function, can
be identified before its final fixed generic assertion. The whole derived CD
must still be bound by its actual SHA-256 through the original report protocol.

`capture_failed_execute` retains finite inner records and the exact host
assertion before the original main removes its owned image/container. It does
not publish a raw failed UART, failed PNG or private log. Root must separately
author and peer-review the operational admission/publication mapping; the
finite records alone never qualify a VM or the image. All old BIOS publication,
whole-UART privacy, report, image, security and manual PNG gates remain required.

BIOS180 predates the separately reviewed Native256 ordinary-password focus
correction. That later correction is conditional on all three Native fixture
flags; copying it alone does not establish BIOS coverage. Observation preserves
the original BIOS behavior. A recorded Source login failure would justify a
separately reviewed generalization with actual pointer geometry and real PAM.
No actual BIOS cause is inferred from this Source preparation.

Source inspection found consistent `/run/t` mount paths, the exact offline CI
profile and BIOS tuple, and no definite installation/composition defect. This
is a bounded source review, not proof that the real installation or boot works.
