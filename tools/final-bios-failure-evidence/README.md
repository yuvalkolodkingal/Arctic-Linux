# Disabled BIOS failure originals observer

This all-ADD Source preparation is based on the exact published f23 observed
BIOS lane. It ships no workflow, marker, ready manifest or runtime dispatch.
All previous product, manifests, workflows, markers and helpers stay byte exact.

The closed actual f23 run returned failure from the original installed-smoke
exit check. It did not publish failed UARTs or PNGs. Source inspection shows
those files remain in the owned host output mount after the original Driver
finishes and the shell chowns that tree to HOST_UID. Original main cleanup
removes its owned container and image, without deleting that mount. The shell
also tails failed UART into its original job log. One Source-derived transport
substitution removes only that optional unscreened failure tail. The original
completion grep and complete embedded Driver remain byte exact.

The explicit adapter keeps the exact original main code object, original
execute, guest bundle, Driver, input, security gates, deadlines and cleanup.
After execute has stopped/reaped its owned group and failed, the adapter
snapshots only the original two UART and four fixed screenshot names, before
main cleanup. Each member must have the host UID, one link, safe mode, regular
type and unchanged acquired generation, through anchored directory FDs.
Signals are blocked through the bounded failure snapshot and FD cleanup, then
restored. This occurs after the original invocation has failed and its process
group is stopped; original VM and harness budgets remain unchanged.

Complete UART original bytes require the unchanged strict external_text gate
before gzip publication. Original PNG bytes require the original chunk/CRC,
geometry and decoder validation plus strict screening of OCR from that same
buffer. Rejected originals remain mode0600 in private/failed-originals. No
redaction, image rewriting, arbitrary filename, private text or rejected-byte
digest is published. OCR is an additional screen with known detection limits;
every published original PNG still needs manual review. Missing/failed OCR
keeps that screenshot private. The future lane needs tesseract installed.

A separate bounded projector retains only complete guest observer records with
the exact context and accepted whole Source vocabulary. A rejected UART may
supply this finite Source assertion without supplying raw UART qualification.
The projector does not export exception messages, operands, unknown fields,
hashes of rejected content or arbitrary labels. It cannot establish input
delivery, PAM success or the actual guest failure cause before a fresh test.

Successful publication stays byte exact. Failed snapshots provide diagnostics
only; all release acceptance, firmware, installation, completion, security and
manual review requirements remain unchanged. Install/host limits are still
2400/6600 seconds. Optional failure OCR has a separate maximum20 seconds per
image after the original invocation. The Source controls use owned real files,
one Python child, actual pinned observer functions and synthetic guest metadata.
They are not an installation, image, OCR accuracy or PAM qualification.
