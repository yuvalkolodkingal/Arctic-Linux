## Actual failure and bounded correction

Run 37527394624 at source `fada20a04c5e8268723a7e5b8784946558dc211c` failed. Its verified official evidence ZIP is 3,095,669 bytes, SHA256 `bf0c03fa945ddf360db48aa029519e9dea7b67cc7ea8771ed4179e96d299a1f5`. The fresh live installation passed 11 checks and exit zero; its installed first pass recorded 43 passes and one unchanged-Nix-version unrun record. Signed old-stable staging passed. The update-cycle kernel and journal reached the exact serial request for that fresh root UUID, but the graphical amber-prompt classifier returned dark and waited 900 seconds. It sent no passphrase. No guest reset, completed transaction or third boot was observed. The later guest=false host-qmp-quit event is cleanup. `diagnosis-v5.json` binds the actual owner and independent evidence reports; their failed outcomes remain unchanged.

The existing transient entry places `console=ttyS0,115200` after `console=tty0`. [Linux serial-console documentation](https://docs.kernel.org/admin-guide/serial-console.html) describes the last distinct console as the device backing `/dev/console`. An observed serial request does not establish that QMP keyboard input reaches that request. V5 therefore replaces only the update helper's one-way serial file backend with a bidirectional UNIX serial connection. [QEMU invocation documentation](https://www.qemu.org/docs/master/system/invocation.html) defines the UNIX socket backend; [actual QEMU 10.2.2 socket source](https://github.com/qemu/qemu/blob/v10.2.2/chardev/char-socket.c) shows received socket bytes forwarded to the guest character device. [Systemd TTY password source](https://github.com/systemd/systemd/blob/v259/src/shared/ask-password-api.c) disables terminal echo for a TTY password read. These sources support the transport design, not an actual successful unlock. The exact disposable guest input route remains VM-unrun.

## Input, identity and evidence gates

The serial connection and QMP endpoint reside in the same fresh private mode-0700 `/tmp/arctic-offline-v5-*` directory. Serial attaches before the controller starts the installed kernel. Earlier firmware bytes can precede attachment; the capture scope is the connected kernel/update console, not a claim to all firmware output. A current UNIX socket must be nonlinked, owned and unchanged by device/inode. `SO_PEERCRED` must identify the exact owned Fedora QEMU executable, PID, UID and `/proc` start time; those identities are rechecked during collection and immediately before input.

The disk/vars have the **host runner's ownership**, distinct from the container's QEMU process ownership: unchanged `tools/test-install.sh` passes host UID/GID and chowns its output after phase one. The driver supplies its actual same-run UID/GID explicitly. The helper requires those exact two owners, fixed paths and no group/other write, records UID/GID/mode/device/inode, and rechecks that snapshot after observation. The driver verifies retained files against its host identity again. No new chown, container user/privilege change or relaxed ownership rule is introduced.

The passed first phase's saved `serial-install.log` SHA256 is retained in driver memory and its manifest, then passed into the update helper. The helper requires that exact file to contain one successful fresh `/dev/vda4` Arctic-root LUKS format/open mapping and one install exit zero. Incoming current serial bytes must contain an ordered systemd boot ID, dracut kernel line and exactly one password request for that root UUID. The actual kernel UUID and unchanged two-console route must agree. A missing, duplicate, stale, reordered, wrong-root, login or error request fails before input. No saved request, graphical classification, login route or blind input serves as a fallback.

Only that verified current request permits one bounded serial write. The attempt is marked before the write, including partial-write failures; there is no retry. The disposable passphrase is not placed in command arguments, QMP, stdout, error text or logs. Only guest-received bytes are collected. Before input they are preserved immediately. After input they are bounded in memory and checked for complete, partial-prefix and ANSI-wrapped password echo before persistence; detected echo withholds all post-input bytes. There are no post-input screenshots, so unexpected echo cannot become a saved frame. Constructor failures explicitly close partial sockets/streams.

The helper preserves received serial bytes, SHA256/size, current root/boot proof, peer proof, QMP events and actual restricted argv. `raw_serial_complete=true` means the safe bytes received by this connection were finalized at its stopping point; on a failure it does not mean a complete boot or transaction. Qualified cycle observation additionally requires serial EOF, one submitted attempt, clean QEMU exit zero and exactly one guest=true guest-reset/guest-shutdown event, without timeout, host quit/signal/error, panic or watchdog. Missing serial, QMP or exit proof fails. A clean observed cycle exit is labelled `guest_cycle_exit_observed_third_boot_required`, never update completion.
